### Q1. Sync Engine

You are building a Sync Engine for applications that maintain an offline copy of server data on users' devices.

The server contains a single table called orders. Each client stores a query (filter), and its local copy must contain exactly the rows satisfying that query.

Whenever the server's orders table changes, the Sync Engine must determine which clients could have an outdated copy and notify them.

Client Queries  
There are n client queries, numbered from 1 to n. These queries remain unchanged throughout the input.  
Each query is equivalent to:  
SELECT * FROM orders WHERE &lt;expression>  
The expression is represented as a tree rather than SQL text.

1. COND Node: A leaf condition compares the value of one column with a fixed value. Examples: amount > 500, status = "completed", quantity &lt;= 10. The allowed comparison operators are: =, >, &lt;, >=, &lt;=  
2. AND Node: An AND node evaluates to true if all of its children evaluate to true.  
3. OR Node: An OR node evaluates to true if at least one of its children evaluates to true.

False Conditions  
A COND condition evaluates to false if:  
- The row does not contain the column being evaluated.  
- The two values being compared have different types.  
For example, comparing amount > 500 against amount = "600" is always false, even though the textual value could represent a number. This type mismatch rule applies to all operators, including =.

Write Operations  
There are q write operations, applied in the given order. Each operation is one of: INSERT, DELETE, UPDATE.  
You are not given the initial contents of the orders table. Each write contains all information about the row(s) affected, and every write must be evaluated independently.

## 2026-09-30 · MNNIT Allahabad · FTE

### Q1. Sync_Engine: live query update notifications

A local-first app keeps a copy of the server's data on every client. Each client subscribes to one live query over a single table, `orders`, and the server must push an update to that client whenever the client's query result could have changed.

There are n subscribed queries, numbered 1 to n. Query i has the form `SELECT * FROM orders WHERE <expression_i>`. Each WHERE clause is supplied as a boolean expression tree rather than SQL text.

- A leaf is a condition `column op value` where op is one of `=, >, <, >=, <=`.
- An internal node AND is satisfied when every child is satisfied.
- An internal node OR is satisfied when at least one child is satisfied.
- Nodes may be nested to any depth.

The table then receives q write operations, applied in the order given. After each write, report every query whose result could have changed, and no others. A query is affected when:
- INSERT: the inserted row satisfies the query's expression.
- DELETE: the deleted row satisfies the query's expression.
- UPDATE: the old row or the new row satisfies the query's expression.

Read from standard input, write to standard output.

**Input format:** The first line contains `n q`. Next come n expression trees, one per query, in order of query ID. A tree begins with an integer T, its node count, followed by T lines describing nodes 1 to T. Node 1 is the root. Each node line is one of:
- `AND k c1 c2 ... ck`: an AND node with k children.
- `OR k c1 c2 ... ck`: an OR node with k children.
- `COND column op value`: a leaf condition.

Child indices refer to nodes of the same tree, and children do not need to follow their parent. The indices alone define the structure.
